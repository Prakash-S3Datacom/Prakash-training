## 4. Non-Functional Requirements

Non-functional requirements define the quality, performance, and constraints of the system.

1. **Performance:** The system should respond to user requests within an acceptable time.
2. **Security:** The system should protect user information and prevent unauthorized access.
3. **Usability:** The application should be easy to understand and use.
4. **Reliability:** The system should work consistently without unexpected failures.
5. **Scalability:** The system should support an increase in users and data.
6. **Maintainability:** The code should be organized and easy to modify.
7. **Availability:** The system should be accessible whenever required.
8. **Compatibility:** The application should work across supported browsers and devices.

## 6. Acceptance Criteria

Acceptance criteria define the conditions that must be satisfied for a feature to be considered complete.

- The feature should work according to the defined requirement.
- Required fields should be validated.
- Invalid inputs should display appropriate error messages.
- Successful operations should provide confirmation.
- The feature should be tested before completion.

## 7. Constraints and Assumptions

### Constraints

- The application must use the technologies approved for the project.
- Development should follow the agreed project timeline.
- The application must follow applicable security practices.

### Assumptions

- Users have access to a supported device and browser.
- Required infrastructure and tools are available.
- Users provide valid information when using the application.
